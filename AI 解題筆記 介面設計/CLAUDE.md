# 專案交接紀錄：AI 解題筆記（手寫白板 + AI 數學檢查）

> 本檔案是給 Claude Code 的完整交接記憶。之前的對話都在 Claude（claude.ai）這邊進行，只完成了「視覺設計稿」（用專屬的 Design 畫布工具做的 5 個畫面 mockup），**還沒有寫任何實際可執行的 HTML/CSS/JS 程式碼**。接下來的程式開發工作由 Claude Code 接手。

## 1. 專案目標與使用者背景

- 這是一個**學校專題**，由多人小組（原始需求中提到小組作業背景）共同開發。
- 核心構想：做一個網站，把 iPad「無邊記」那種**無邊界手寫白板**的體驗，結合 **AI 批改**。
- 關鍵差異化功能：**算數學算錯時，AI 要指出「過程中哪一步出錯」，而不是只判斷最終答案對或錯。**
- 進階功能：AI 要能**分析使用者在某個科目/單元中「經常出錯的步驟類型」**，並給出個人化學習建議。
- 已確認的技術事實：Apple 的「無邊記」**沒有對外開放 API**，所以不是去串接無邊記本身，而是**在網站裡自己做一個同類型的手寫白板**來取代它。
- 整體系統最終會包含：手寫白板 → 筆跡辨識（OCR）→ 逐步驗算 → 錯誤分類與解釋 → 錯題紀錄與學習分析儀表板。完整架構見下一節。

## 2. 系統總體架構（長期願景，尚未實作）

這是完整專題的架構藍圖，**目前階段只做前端視覺/靜態雛形**，以下內容供未來串接後端時參考，目前不必實作。

```
[瀏覽器：HTML/CSS/JS 手寫白板]
   │ ① 框選要檢查的算式 → 轉成圖片
   │ ② fetch() 送到後端
   ▼
[後端伺服器：建議 Python FastAPI]
   │ ③ 呼叫多模態 AI（如 Claude API）讀出逐行算式 → 回傳 JSON
   │ ④ 前端顯示「AI 讀到的算式」讓使用者確認/修改
   │ ⑤ 用 SymPy（或其他 CAS）逐步比對相鄰兩步是否數學上等價，找出第一個錯誤步驟
   │ ⑥ 再呼叫 AI 針對該步驟寫出錯因說明，並依分類表歸類
   ▼
[資料庫：建議 Supabase 或 Firebase]
   ⑦ 存每次檢查的紀錄（使用者、題目、單元、錯誤步驟、錯誤類型、時間）
   ⑧ 前端「學習分析」頁讀取統計資料，用 Chart.js 等工具畫圖
```

**為什麼需要後端（不能全部用前端 JS 做）：**
- AI 的 API 金鑰不能放在前端 JavaScript 裡，會被任何人用瀏覽器開發者工具看到並盜用。
- 逐步驗算要用 SymPy（Python 套件），所以後端建議用 Python。

**前後端溝通的 JSON 格式範例（未來串接用）：**
```json
{
  "steps": ["2x + 3 = 7", "2x = 10", "x = 5"],
  "error_step": 1,
  "error_type": "移項變號錯誤",
  "explanation": "把 +3 移到右邊時應該變成 -3，所以是 7 - 3 = 4",
  "hint": "再檢查一次移項時的符號"
}
```
（`error_step` 是以 0 或 1 為起始索引，實作時需與前端對齊；上例沿用最終設計稿的例題。）

**建議的範圍收斂：** 先只支援「國中一元一次／一元二次方程式」，因為步驟清楚、容易用 CAS 驗證。幾何證明、應用題難度高很多，列為「未來展望」，目前不做。

**完整錯誤分類表（規劃中，供未來擴充參考）：**
移項變號錯誤、分配律錯誤、四則運算錯誤、約分錯誤、抄錯數字、公式記錯。
（目前視覺設計稿中實際出現並有具體文案的是前五項；「公式記錯」是早期規劃保留的擴充類別，尚未在畫面中出現。）

**部署建議（未來）：** 前端可放 GitHub Pages / Vercel，後端放 Render 這類支援 Python 的平台。

## 3. 目前這個階段的任務（Phase 1：前端視覺雛形）

**使用者明確要求的目標：**
先只做**前端網頁的視覺效果**，要「精美、好操作」，**不是陽春雛形**。**AI 算數檢查的部分目前先不用真的串接後端/API**——也就是說，這階段 AI 檢查功能可以是**靜態展示（用寫死的範例資料模擬整個流程）**，不用真的做辨識或驗算邏輯。

---

## 4. 明確規則：要做 / 不要做

### 必須做到
1. **三個程式碼檔案要分開**：`index.html`、`style.css`、`script.js`（或等效命名），**不可以把 CSS 和 JS 全部寫在同一個 HTML 檔案裡**。
2. 筆記功能要有：**方格紋背景**（可切換方格／橫線／空白）、**多種顏色的畫筆**、**橡皮擦**。
3. AI 檢查流程走「**框選（拖曳矩形）**」而不是「畫筆手繪圈選」——原因：畫筆圈選會跟學生平常圈重點的筆跡混淆、圈選痕跡會留在筆記裡難清除、手畫的圈不規則難判斷邊界。
4. AI 標註顏色（紅色系）**只保留給 AI 使用**，畫筆調色盤裡**不可以提供紅色**，避免學生分不清哪些是自己寫的、哪些是 AI 標的。
5. 辨識完成後要有「**確認算式**」步驟，讓使用者可以看到並修改 AI 讀到的內容，再進入驗算，避免把辨識錯誤誤判成計算錯誤。
6. 錯誤回饋邏輯：**先給簡短提示（hint），使用者主動點開才顯示完整解釋**，不要一開始就把答案攤開。
7. 版面以 **iPad 橫向**尺寸為主要設計基準（視覺設計稿用 1194×834 px 作為單一畫面參考尺寸）。
8. 完成後要**教使用者怎麼開啟這三個檔案**（本機開啟方式）。

### 不要做
1. 不要把這階段的 AI 檢查功能做成真的後端串接／真的呼叫 AI API／真的做 OCR 辨識或 SymPy 驗算——**這階段只需要靜態模擬**。
2. 不要去串接或模仿「無邊記」的任何官方 API（它沒有開放）。
3. 不要把畫筆調色盤設計成包含紅色。
4. 不要省略「確認算式」這個中間步驟。
5. 不要把完整解釋預設展開顯示。

### 5.3 風格規則

- 圓角偏大（卡片 16–24px、按鈕 10–13px、輸入框 10–11px）。

- 浮動工具列/卡片都用白底 + 圓角 + 陰影，營造「飄浮在紙上」的層次感。

### 6.2 畫面二：框選模式（Select）

- 整體背景變暗（`rgba(20,24,45,0.58)`），只有選取框範圍內的筆記清楚可見。
- 選取框：白色虛線框 + 靛藍實線外框，四個角有白底靛藍邊框的圓形控制點（可拖曳調整大小）。
- 選取框上方標籤：「已選取 4 行算式」（打勾 icon + 靛藍底白字）。
- 畫面上方置中有浮動說明卡：icon + 「**拖曳框住要檢查的算式**」標題 + 「框外的筆記不會被讀取，可拖曳四個角調整大小」說明文字 + 「取消」按鈕。
- 選取框下方有浮動動作列：「**重新框選**」（次要按鈕）＋「**開始檢查**」（主要靛藍按鈕，星形圖示）。

### 6.3 畫面三：確認算式（Confirm）

- 背景為半透明深色遮罩（`rgba(20,24,45,0.45)`）蓋在筆記頁上。
- **右側滑出面板**（寬 470px，貼右側，左側圓角，陰影）。
- 面板內容由上到下：
  1. **進度指示條**：框選（已完成，綠勾）→ 確認算式（進行中，靛藍數字 2）→ AI 檢查（未開始，灰色數字 3），用橫線連接三個階段。
  2. 標題「**AI 讀到的算式是這樣嗎？**」＋說明文字「對照你的手寫，有讀錯的地方直接點擊修改，避免把辨識錯誤當成計算錯誤。」
  3. 「你的手寫」區塊：灰色標籤 ＋ 方格紋小畫布，顯示原始手寫內容（唯讀參考用）。
  4. 「AI 辨識結果」區塊：每一行一個可編輯輸入框，前面有小標籤（題目／步驟1／步驟2／步驟3）。**其中一行（步驟2）要特別標示為「字跡模糊」狀態**：琥珀色邊框＋底色，下方加警告文字「這行字跡較模糊，請再確認一次」（含警告三角 icon）。
  5. 單元偵測列：「單元：一元一次方程式（自動判斷）」＋「更改」連結。
  6. 底部按鈕：「重新框選」（次要）＋「**正確，開始檢查**」（主要靛藍、滿版寬、星形圖示）。

### 6.4 畫面四：錯誤標註與提示（Result）

**Header：** 同畫面一的 app 名稱/麵包屑/課程名，右側多一個「**AI 標註**」開關（toggle switch，紅色＝開啟狀態，可關閉隱藏所有 AI 標註），以及「AI 檢查」按鈕。

**主畫布標註：**
- 原手寫內容照常顯示；**出錯步驟之後的步驟要降低透明度**（約 0.55 opacity），視覺上表示「這些步驟的正確性建立在錯誤之上、暫不評判」。
- 出錯的那一行：紅色虛線圓角框包住，左上角有紅色圓形數字徽章「1」標示是第幾步出錯，旁邊有小紅標籤顯示關鍵詞（例如「+3 → ?」）。
- 從錯誤步驟往下有一條淺紅色豎線連到後面步驟，並有文字「之後兩步受第 1 步影響」。
- 有一條紅色虛線水平箭頭，從錯誤步驟指向右側的提示卡片。

**右側浮動提示卡片（寬 392px）：**
1. 卡頭：警告 icon（琥珀色圓底）＋標題「第 1 步出了點問題」＋副標「錯誤類型：**移項變號錯誤**」＋關閉按鈕。
2. **步驟清單**（有邊框的清單區塊）：依序列出 題目/步驟1/步驟2/步驟3，每行左側有狀態 icon——
   - 題目／正確步驟：綠色勾勾 icon
   - **出錯步驟**：紅色叉叉 icon，整行紅色底色+紅色粗體文字
   - 尚未判斷的後續步驟：灰色「–」icon，文字灰階淡化
3. **提示框**（琥珀底）：燈泡 icon ＋「提示」標籤 ＋ 簡短引導問句：「把 +3 從等號左邊移到右邊時，它的符號應該怎麼變？」（**不直接給答案**）。
4. 可展開的「**還是想不到？看完整解釋**」（`<details>`/手風琴元件，預設收合）：展開後顯示完整解釋文字：「移項要變號：+3 移到右邊變成 −3，所以 2x = 7 − 3 = 4，得到 x = 2。」
5. 底部兩個按鈕：「我自己訂正」（次要）＋「訂正後再檢查」（主要靛藍）。

### 6.5 畫面五：學習分析（Analysis）

**Header：** 返回按鈕、「學習分析」標題、「範例資料」琥珀色提示標籤（說明目前數字是示意用、非真實資料）、時間範圍切換 Tab（本週／本月／全部，預設選中「本週」）。

**第一列：4 個統計卡片（橫向排列）：**
- 本週檢查：32 題
- 一次就算對：68%
- 比上週進步：+9%（綠色）
- 連續練習：5 天

## 7. 範例資料（Demo Data，供這階段靜態展示使用）

這階段**不需要真的辨識或驗算**，所有流程都可以用下面這組固定的範例資料跑過整個 UI 流程（框選 → 確認 → 標錯 → 分析）。

**課程資訊：**

- 課程：第 3 課　移項法則

**例題 3（用於主要示範流程，包含錯誤）：**
```

步驟1：2x = 7 + 3     ← 這裡是錯的（應該是 2x = 7 - 3）
步驟2：2x = 10
步驟3：x = 5
```
- 錯誤發生在**步驟 1**。
- 錯誤分類：**移項變號錯誤**。
- 提示文案：「把 +3 從等號左邊移到右邊時，它的符號應該怎麼變？」
- 完整解釋文案：「移項要變號：+3 移到右邊變成 −3，所以 2x = 7 − 3 = 4，得到 x = 2。」

**例題 4（裝飾用，正確示範，不含錯誤互動）：**
```
題目：3(x − 2) = 12
步驟1：3x − 6 = 12
步驟2：3x = 18
步驟3：x = 6
```

**旁註重點（手寫筆記裝飾文字）：** 「重點：移項要變號！」「＋ 移過去變 －，× 移過去變 ÷」

**「確認算式」畫面的辨識模擬：** 4 行內容對應例題 3 的題目＋3 個步驟，其中「步驟 2（2x = 10）」要標示為「字跡模糊、請再確認一次」的警告狀態（純粹是 UI 示範，內容本身不必是錯的）。

**錯誤分類清單（下拉選單/標籤會用到的完整選項）：**
移項變號錯誤、分配律錯誤、四則運算錯誤、約分錯誤、抄錯數字。

## 11. Phase 1 實作紀錄（2026-11-26 完成）

### 11.1 檔案
- `index.html`：所有畫面的 HTML 結構 + inline SVG 圖示（`<symbol>` sprite，用 `<use href="#i-xxx">` 引用）。
- `style.css`：設計系統 tokens（`:root` CSS 變數）＋各畫面樣式。畫面狀態用 `body[data-mode]`（draw / select / confirm / checking / result）與 `body.has-result` / `has-card` / `ai-hidden` 控制。
- `script.js`：所有互動邏輯，單一 IIFE，依區塊分段（範例資料 → 狀態 → 繪圖 → 平移縮放 → 手寫輸入 → 橡皮擦 → 復原重做 → 工具列 → 頁面 → 框選 → 確認算式 → 錯誤標註 → 學習分析 → 事件綁定）。
- `.claude/launch.json`：本機預覽伺服器設定（`python -m http.server 5173`），只是開發測試用。

### 11.2 已實作的重點
- **畫布是無邊界白板**：筆跡存「世界座標」，畫面有 `view2d = {x, y, zoom}`；滾輪/觸控板平移，Ctrl+滾輪或雙指捏合縮放（50%–200%），點百分比回到 100%。格線是 `.paper` 的 CSS 背景（跟著平移/縮放），筆跡畫在獨立的 `<canvas id="ink">`。
- **筆跡資料**：`{ color, width, points: [[x, y, pressure], ...] }`，每頁 `strokes` 陣列；復原/重做用「整個陣列的快照」堆疊（每頁各自獨立，上限 100 步）。
- **Apple Pencil**：用 `pointerType === 'pen'` 的壓力調整線寬；一旦偵測到筆，手指只負責平移/縮放、筆在寫字時忽略手掌觸控（防誤觸）。沒有筆的裝置手指可以直接寫。
- **橡皮擦**：整筆擦除＝碰到就刪整筆；局部擦除＝先補點再把半徑內的點挖掉、切成多段新筆跡。
- **範例內容**（第 2 頁的例題文字、螢光筆底色）是 canvas 上的「文字物件」（`page.items`），不會被擦掉；橘色圈圈是一般筆跡，可以擦。
- **自動儲存**：筆跡、紙張樣式、工具設定存在瀏覽器 `localStorage`（key：`ai-solve-notes/v1`）。想回到初始範例：在瀏覽器開發者工具刪掉這個 key。
- **AI 檢查流程（全部靜態模擬）**：框選時會判斷框內有幾行範例算式（例題 3 → 錯誤示範；例題 4 → 全部正確示範；框到其他筆跡 → 提示示範版只能檢查例題）。確認算式的輸入框可以修改，結果卡片的步驟清單會顯示修改後的文字，但錯誤判斷固定是寫死的。
- **學習分析**：本週/本月/全部三個 Tab 都有假數據（本週＝規格數字；本月、全部是自行編的示意數字）。網址加 `#analysis` 直接開分析頁。
- **快捷鍵**：P 畫筆、E 橡皮擦、1–6 換顏色、Ctrl+Z 復原、Ctrl+Shift+Z / Ctrl+Y 重做、按住空白鍵拖曳平移、Esc 取消框選/關閉面板。
